HELP & FAQ

使用说明与常见问题

快速开始

  1. 确认内网 DNS（默认 192.168.2.19）和外网 DNS（默认 8.8.8.8），修改后点“保存配置”。
  2. 点“打开内网”“打开外网”或“同时打开内网 + 外网”。
  3. 之后都在弹出的浏览器窗口里操作，不要再点桌面上的 Chrome 图标。内网窗口需要能访问内网 DNS；不在公司网络时请先连 VPN。

怎么区分两个窗口

内网 蓝色边框 DNS 192.168.2.19 · 端口 18080 标题前缀 【内网环境】
外网 红色边框 DNS 8.8.8.8 · 端口 18082 标题前缀 【外网环境】

Chrome / Edge 会显示页面 2px 彩色边框和标签页标题前缀；Firefox 使用窗口顶部 6px 色条。 颜色可以在主界面自定义，修改后下次打开浏览器生效。同时打开时，内网窗口在左，外网窗口在右。

Agent / 自动化如何识别

推荐

优先读取页面内的稳定标识，不要只靠颜色或窗口位置判断。Chrome / Edge 页面加载后，可直接在页面上下文执行： 

const env = document.documentElement.dataset.dualdnsEnv;
// "internal" 内网 / "external" 外网

const info = window.__DUALDNS_ENV__;
// { env, label, dns }
// label: "内网环境" / "外网环境"
  • dataset.dualdnsEnv：internal 或 external，最稳定的判断依据。
  • dataset.dualdnsLabel：中文标签；dataset.dualdnsDns：当前 DNS。
  • Chrome / Edge 的标签页标题始终带 【内网环境】 或 【外网环境】 前缀。
  • 代理端口：内网 18080、外网 18082。可从浏览器进程的 --proxy-server 启动参数或本地代理确认；目标网站地址栏不会显示代理端口。
  • 同时打开时，内网窗口默认在屏幕左侧，外网窗口在右侧。

Firefox 不支持页面内注入，Agent 可改用窗口顶部色条、独立配置目录或代理端口判断。 第一次打开页面时标识注入可能有短暂延迟，读取不到时等待页面加载完成或稍后重试。

局域网快传

“局域网快传”用于在同一 Wi-Fi / 局域网内发现同事的电脑，发送短消息或文件。消息和文件只在本机与同事电脑之间传输，不上传到 Gitee、GitHub 或任何云端服务。

  • 双方都需要打开 DualDNS Browser，并连接到同一个可互访的局域网。
  • 自动发现使用 UDP 18191，消息和文件传输使用 TCP 18190。Windows 首次询问防火墙权限时请选择允许“专用网络”。
  • 在线同事列表固定高度并独立滚动。同事较多时，可以在上方搜索框按电脑名称、IP 或 macOS / Windows 快速筛选。
  • 公司 Wi-Fi 开启 AP 隔离 / 客户端隔离时，设备之间无法互访，自动发现会失败；可以尝试让同事把 IP 发给你后手动添加。
  • 点击同事后可以发消息或选择文件。收到的文件会先暂存，点“保存”后才会进入下载目录：macOS 为 ~/Downloads/DualDNS Transfers，Windows 为 %USERPROFILE%\Downloads\DualDNS Transfers。
  • 收到新消息或文件时，系统会弹出通知；如果收不到通知，请在系统设置中允许 DualDNS Browser 发送通知。
  • 不想被所有同事看到时，可以打开“隐身模式”，只勾选允许发现你的电脑。隐身期间未勾选的设备无法发现你，也不能给你发消息或传文件。
  • 想在自己的两台电脑之间互传：先让两台电脑正常发现对方，把对方加入隐身名单，再开启隐身。隐身期间不能手动添加新 IP，需要新增设备时先关闭隐身。
  • 单个文件最大 2 GB；文件越大，传输时间越长。传输出错时先确认双方仍在同一网络、应用未退出，并检查防火墙。
  • 隐身只限制应用层的设备发现和连接，不会加密局域网流量。请只在可信的公司网络或家庭网络使用，不要在公共 Wi-Fi 上传输敏感文件。

检查更新

主界面右上角的版本号按钮可以随时检查更新。应用启动时也会自动静默检查一次；发现新版本时会显示一条提示，不打断正常使用。

  • 默认“自动”模式会优先请求 Gitee 国内源，失败后自动切换到 GitHub 国外源。
  • 也可以在更新弹窗中手动选择 Gitee 或 GitHub。国内外网络环境不同，国内网络建议用 Gitee，海外网络建议用 GitHub。
  • 发现新版本后，点击“立即更新到 vX”即可在应用内下载；文件会先校验 SHA256，然后应用自动退出、安装并重启。
  • 更新重启时不会关闭已打开的浏览器；重启后会自动检测仍在运行的浏览器，并恢复对应环境的代理和页面标识。
  • 应用内更新失败时，可以点“打开发布页”手动下载。更新不会删除 DNS 配置和浏览器登录状态。

关闭、托盘与彻底退出

  • 点击窗口右上角的 × 只会隐藏到系统托盘，本地 DNS 代理继续运行，已经打开的浏览器可以正常继续使用。
  • 需要彻底退出时，右键托盘图标，选择“退出并关闭浏览器”。
  • 彻底退出会停止代理，并关闭由本应用打开的浏览器窗口，避免留下无法上网的窗口。
  • 如果只想暂时收起主界面，直接点 × 即可；下次从托盘图标重新打开。

常见问题

检查更新失败怎么办？

先确认能正常访问 gitee.com 或 github.com，再到更新弹窗中手动切换更新源重试。公司网络限制外部访问时，可以先用手机热点测试。

点 × 关闭窗口后，浏览器还能用吗？

可以。点 × 只是隐藏到系统托盘，本地代理继续运行。要彻底退出，请使用托盘菜单的“退出并关闭浏览器”。

更新重启后浏览器还需要重新打开吗？

不需要。应用更新前会保留浏览器窗口，重启后自动检测并恢复对应环境的代理；如果浏览器已被手动关闭，就不会再启动对应代理。

Windows 第一次启动或第一次打开浏览器有点慢？

首次启动需要初始化 WebView2 运行时，第一次打开浏览器也要创建独立配置目录，通常会比之后慢。新版本会在界面首帧准备好后再显示窗口，避免启动时出现长时间白屏；后续启动会明显更快。

macOS 上看不到同事的电脑？

先到“局域网快传”页点“局域网权限”，再点“发起局域网访问”。应用会显示探测了多少个地址；系统弹出本地网络授权时选择“允许”。如果点“打开系统设置”后只停在“隐私与安全性”首页，请向下滚动并点“本地网络”，确认 DualDNS Browser 已打开。重装应用通常会沿用之前的系统授权，没有再次弹窗不等于没有权限。如果两台电脑分属不同网段或公司开启了设备隔离，自动发现也可能受限，可以手动添加对方 IP。

Windows 上看不到同事的电脑？

到“局域网快传”页点“局域网权限”，再点“发起局域网访问”和“打开防火墙设置”。在 Windows 防火墙中允许 DualDNS Browser 通过“专用网络”，然后重新打开应用。公司 Wi-Fi 开了客户端隔离时，仍需手动添加对方 IP。

怎么只让自己的另一台电脑看到我？

先在正常模式下让两台电脑互相出现在在线同事列表，再打开“隐身模式”，勾选你的另一台电脑并保存。之后只有名单中的电脑能发现你。隐身期间不能手动添加新 IP；需要新增设备时，先关闭隐身模式完成发现和勾选。

开了 Clash / VPN 的 TUN 模式后，外网窗口打不开网站？

外网窗口会绑定物理网卡出口，自己向填写的外网 DNS 查询并直连目标 IP，不读取本机 hosts，也不经过 Clash 的 DNS 分流规则。内网窗口仍然只走内网 DNS。若仍失败，请确认外网 DNS 和物理网卡可以正常上网。

提示端口被占用？

本机 18080 或 18082 被其他程序占用。关掉占用程序，或在底部点“停止本地代理”后重试。

第一次打开浏览器是空白页 / 要重新登录？

两个环境使用独立配置目录，登录状态互不影响，首次需要分别登录，属于正常现象。

应用图标显示空白或还是旧图标？

确认运行的是安装包里的应用，不要直接运行开发目录中的二进制文件。macOS 可执行 killall Finder 或重启；Windows 请重新安装最新 Setup 版。

安装提示

安装包没有购买代码签名证书。macOS 首次打开请右键应用 → 打开 → 再点“打开”；若提示“已损坏”，执行 xattr -dr com.apple.quarantine "/Applications/DualDNS Browser.app"。 Windows SmartScreen 提示时点“更多信息” → “仍要运行”。

LOCAL NETWORK

让同事能看到你

局域网快传需要系统允许本应用访问本地网络。第一次使用时，macOS 通常会自动弹出授权。

等待授权 如果同事看不到你，或你搜不到同事，按下面步骤检查。
  1. 1
    打开系统设置

    进入“隐私与安全性 → 本地网络”。

  2. 2
    打开 DualDNS Browser 的开关

    如果列表里没有本应用，先点“发起局域网访问”，再回到系统设置查看。

  3. 3
    完全退出后重新打开

    从托盘菜单选择“退出并关闭浏览器”，再重新启动，局域网发现会恢复。

重新安装应用时，系统通常不会再次弹窗，因为之前的授权记录可能仍然保留。
